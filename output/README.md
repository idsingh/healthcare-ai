# Output: `service_output.json`

This is the service's **actual output** for `extracted_text.txt` (the EOC excerpt), not a
hand-written example. It is committed so it can be read without running anything.

| | |
|---|---|
| Input | `../extracted_text.txt` — 4,624 characters, pages 115–116, ends mid-sentence |
| Output | `service_output.json` — 2 packages, 22 CDT codes, 48/48 fields grounded |
| Model used for this file | **offline stub** (`stub/deterministic-offline`) — see [With an external model](#with-an-external-model) |
| Validation | `passed: true`, `needs_review: true` (the excerpt is truncated) |

---

## 1. How it was generated

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m tools.extract_cli extracted_text.txt      # -> output/service_output.json
```

No API key required. The same result comes back over HTTP:

```bash
.venv/bin/uvicorn app.api.main:app                            # terminal 1
curl -X POST localhost:8000/extract -H 'content-type: application/json' \
     -d "$(python3 -c 'import json;print(json.dumps({"text":open("extracted_text.txt").read()}))')"
curl localhost:8000/extract/<job_id>                          # result under "result"
```

What happens in between:

```
extracted_text.txt
   │
   ├─ preprocess    normalize unicode/dashes, drop repeated page headers and footers,
   │                keep two views: line-preserving (for prompts) and flattened (for offsets)
   ├─ segment       cut on package headings; label each line as benefit-column or cost-column
   │                (the source is a two-column table flattened into reading order)
   ├─ scan          regex scanners read every number: premiums, maximums, %, CDT codes
   ├─ LLM pass      one call per package, structured output against a Pydantic contract,
   │                asked only for meaning: service names, limits, cost-share scope, exclusions
   ├─ merge         scanners win on digits; the model's items are kept only if their quote
   │                resolves inside that package's character span
   └─ validate      5 rules; an ungrounded or fabricated value is nulled, not emitted
```

## 2. How to read one field

Every value in the file has the same shape, so learning one teaches all of them:

```jsonc
"benefit_maximum": {
  "value":  { "amount_usd": 500.0, "period": "per_year", "applies_to": "preventive dental benefits" },
  "status": "found",           // found | not_stated | ambiguous | unverified | truncated
  "confidence": 0.97,
  "source": "deterministic",   // deterministic (regex) | llm | merged (both agreed)
  "evidence": {
    "quote": "plan will pay up to $500 for preventive dental benefits each year",
    "start": 1853, "end": 1918,   // character offsets into the normalized document
    "page": 115
  }
}
```

Two conventions worth knowing:

- **`status: "not_stated"` with `value: null` is a success**, not a gap. `document.issuer` is
  null because the carrier is never named separately from the plan name. The service does not
  infer it.
- **`needs_review: true` is independent of `passed`.** This run passed every validator and
  still asks for a human, because the excerpt is cut off mid-sentence.

## 3. Where each number came from

Counted from this exact file — 49 evidence-bearing nodes:

| `source` | Count | Fields | Depends on the model? |
|---|---|---|---|
| `deterministic` | 32 | plan name/year/form id, package names, **both premiums**, **both benefit maximums**, all 22 CDT codes + descriptions | No |
| `merged` (scanner + model agreed) | 11 | network restrictions, services with their limits, cost-share entries | Numbers no, wording yes |
| `llm` | 5 | package 1's exclusions | Yes |
| `null` (correct abstention) | 1 | `document.issuer` | No |

So **every dollar amount, percentage and procedure code in this file was read by a regex, not
generated by a model.** The model is asked for meaning only, and its answer is discarded
unless it comes with a quote that exists in the source.

## 4. Verify it yourself

This re-checks every quote and offset in the output against the raw text file, independently
of the service's own validation:

```python
import json, re, unicodedata
collapse = lambda t: re.sub(r"\s+", " ", unicodedata.normalize("NFKC", t)
                            .translate(str.maketrans("–—−‐‑", "-----"))).strip()
raw  = collapse(open("extracted_text.txt").read())
doc  = json.load(open("output/service_output.json"))
nodes = [*doc["document"].values()] + [n for p in doc["packages"]
           for n in [p["name"], p["premium"], p["benefit_maximum"], p["network_restriction"],
                     *p["services"], *p["codes"], *p["cost_share"], *p["exclusions"]]]
nodes = [n for n in nodes if isinstance(n, dict)]
bad = [n for n in nodes if n.get("evidence") and collapse(n["evidence"]["quote"]) not in raw]
print(f"{len(nodes) - len(bad)}/{len(nodes)} quotes found verbatim in extracted_text.txt; {len(bad)} not")
```

Expected: `48/48 quotes found verbatim in extracted_text.txt; 0 not`
(49 nodes, one of which — `document.issuer` — is a correct null with no evidence).

(Offsets in the file are relative to the service's normalization, which removes repeated page
headers and footers; the snippet above therefore checks quotes, not offsets. The service
checks both — `app/application/validation.py`, `GroundednessRule`.)

## 5. What the service flagged, and why each flag is correct

| Flag | Why |
|---|---|
| `document.truncated` | The excerpt ends `"...oral surgery dental"` mid-sentence |
| `invariants.exclusions_not_stated` on `pkg_2` | Package 2's exclusions are not in the excerpt. The empty list means *not observed*, never *none apply* |
| `review.low_certainty` on `pkg_2.cost_share[2]` | The 50% coinsurance sentence is cut off, so it is `status: "truncated"` — the percentage is kept, the completion is not invented |

Also worth checking against the source by hand:

- Package 1's codes **span the page break**: D0270–D0330, D1110 and D1208 sit on page 116,
  after a repeated running header, and are still attached to package 1.
- `"Coverage is available from LIBERTY Dental providers only"` appears in **both** packages;
  each is anchored to its own package's character span, not to the first occurrence.
- Package 2 carries a $0 copay *and* 20%/50% coinsurance. That is not flagged as a
  contradiction because they apply to disjoint service sets.

## With an external model

This file was produced with the offline stub — `run.model_id` says so. To produce it with a
real model:

```bash
export EXTRACT_LLM_PROVIDER=openrouter
export EXTRACT_OPENROUTER_API_KEY=sk-or-...
export EXTRACT_MODEL_ID=openai/gpt-5.6-luna     # any OpenRouter model slug
.venv/bin/python -m tools.extract_cli extracted_text.txt
```

Nothing else changes: same pipeline, same contract, same validators. The stub and the
provider client implement one port (`app/domain/ports.py: LLMClient`), chosen in
`app/api/deps.py`.

### What stays identical

Verified by construction — these never pass through the model:

| Field | Why it cannot move |
|---|---|
| Both premiums ($13.00, $32.00) | Read by `PremiumScanner`; the model is not even asked for a premium |
| Both benefit maximums ($500, $1,000) | Read by `BenefitMaximumScanner` |
| All 22 CDT codes and their descriptions | Read line-by-line by `CdtCodeScanner` |
| Cost-share amounts and percentages (0, 20, 50) | Read by the copay/coinsurance scanners |
| Package names, plan name, plan year, form id | Heading and header anchors |
| Limit counts where a scanner matched the phrase | `merge.py` prefers the scanner; a disagreeing model count is recorded in `notes` and discarded |

If a model returns a number that contradicts a scanner for the same sentence, the scanner
wins and the discarded claim is written into that field's `notes` — see
`tests/test_llm_reliability.py::test_model_count_loses_to_the_scanner_on_the_same_phrase`.

### What would change

Expected, not measured — these are the model-dependent parts of the output:

| Field | Likely change with a real model |
|---|---|
| `services[].name`, `.category` | Better naming and grouping. The stub derives names from the frequency phrase, so it produces `"Dental X-rays"` from one sentence; a model may split or label them more sensibly |
| `services[].limit.raw` for compound limits | The X-ray sentence carries three quantities ("one full-mouth *or* panoramic", "one set of bitewings", "up to seven periapical"); the stub keeps one, a model should represent all three |
| `cost_share[].applies_to` | Richer scope text and better `service_ids` attachment — the stub could not link package 2's 20%/50% to any service because restorative/endodontic services are never itemised in the excerpt |
| `exclusions[].text`, `.kind` | The largest difference: normalization of free prose is exactly what the deterministic layer cannot do |
| `benefit_domains`, package 2's vision handling | A model should note that the package promises vision coverage with no vision detail in the excerpt |
| `run.model_id`, `llm_calls`, `llm_retries` | Real values; latency goes from ~10 ms to seconds, and the run costs tokens |
| `validation.flags` | May gain `groundedness.*` or `review.low_certainty` entries if the model produces anything unsupported — those values are withheld, not emitted |

### What could go wrong, and what the output would look like

| Failure | Result in the file |
|---|---|
| Wrong model slug, bad key | `LLMPermanentError`, no retries; every package `degraded: true`, job status `partial`, all deterministic fields still present |
| Rate limit / 5xx / timeout | Up to 3 attempts with jittered backoff (`run.llm_retries` > 0); if exhausted, that block degrades — the document still completes |
| Reply is not valid JSON, or breaks the contract | One repair round-trip carrying the validator error; if it fails again, that block degrades |
| Model invents a benefit or quotes text that is not in the document | The item is dropped or set to `status: "unverified"` with its value nulled, and the document is flagged |
| Model inflates a number with a real quote attached | `numeric.not_in_evidence` error → value withheld, `validation.passed: false`, job status `partial` |

Each row has a test in `tests/test_llm_reliability.py`.

### How to compare the two runs

```bash
cp output/service_output.json /tmp/stub.json
EXTRACT_LLM_PROVIDER=openrouter EXTRACT_OPENROUTER_API_KEY=sk-or-... \
  .venv/bin/python -m tools.extract_cli extracted_text.txt -o /tmp/real.json
diff <(jq -S '.packages[] | {premium, benefit_maximum, codes}' /tmp/stub.json) \
     <(jq -S '.packages[] | {premium, benefit_maximum, codes}' /tmp/real.json) && echo "numbers identical"
diff <(jq -S '.packages[].exclusions' /tmp/stub.json) \
     <(jq -S '.packages[].exclusions' /tmp/real.json)   # this is where the model earns its cost
```

The first diff should be empty. The second is the interesting one.
